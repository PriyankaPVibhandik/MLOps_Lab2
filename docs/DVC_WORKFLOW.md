## 3. DVC Initialization

DVC was initialized inside the existing Git repository using:

```bash
dvc init
```

This created the `.dvc/` directory and `.dvcignore`.

The DVC configuration was then committed to Git:

```bash
git add .dvc .dvcignore
git commit -m "chore: initialize DVC in the repository"
```

Git therefore tracks the DVC configuration and metadata, while DVC manages the actual dataset contents.

---

## 4. DVC Remote Configuration

For classroom and local experimentation, a local folder was configured as the DVC remote.

The remote storage directory was created using:

```bash
mkdir -p ~/dvc-remote-storage
```

The directory was then configured as the default DVC remote:

```bash
dvc remote add -d myremote ~/dvc-remote-storage
```

The configuration was committed to Git:

```bash
git add .dvc/config
git commit -m "chore: configure local DVC remote"
```

The configured remote can be checked using:

```bash
dvc remote list
```

Expected configuration:

```text
myremote    /c/Users/Admin/dvc-remote-storage    (default)
```

The local remote simulates a shared/cloud storage location for the purpose of this experiment.

## 5. Dataset Creation

A sample Iris dataset was generated using the scikit-learn dataset:

```python
import pandas as pd
from sklearn.datasets import load_iris

iris = load_iris(as_frame=True)

df = iris.frame

df.to_csv("data/raw/iris_v1.csv", index=False)

print(f"Saved {len(df)} rows to data/raw/iris_v1.csv")
```

The dataset contains:

```text
150 rows
```

and was stored at:

```text
data/raw/iris_v1.csv
```

---

## 6. DVC Dataset Tracking

The dataset was added to DVC using:

```bash
dvc add data/raw/iris_v1.csv
```

This generated the DVC metadata file:

```text
data/raw/iris_v1.csv.dvc
```

DVC also created:

```text
data/raw/.gitignore
```

so that the actual CSV file is not tracked directly by Git.

The DVC metadata was then committed to Git:

```bash
git add data/raw/iris_v1.csv.dvc data/raw/.gitignore

git commit -m "data: add iris_v1 raw dataset (150 rows) tracked via DVC"
```

The corresponding Git commit was:

```text
602aa4a
```

Finally, the dataset was uploaded to the configured DVC remote:

```bash
dvc push
```

The push successfully transferred the dataset to the local DVC remote.

## 7. Standard DVC Versioning Cycle

For every dataset modification, the following workflow is followed:

```text
Modify Dataset
      ↓
dvc add
      ↓
git add
      ↓
git commit
      ↓
dvc push
```

### Step 1 — Modify the dataset

The dataset is modified or regenerated using the appropriate Python script.

Example:

```bash
python src/augment_data.py
```

### Step 2 — Update DVC metadata

```bash
dvc add data/raw/iris_v1.csv
```

DVC calculates a new hash for the modified dataset.

### Step 3 — Stage the DVC metadata in Git

```bash
git add data/raw/iris_v1.csv.dvc
```

### Step 4 — Commit the new dataset version

```bash
git commit -m "data: augment iris dataset with 20 synthetic rows (150 -> 170)"
```

### Step 5 — Push the dataset to the DVC remote

```bash
dvc push
```

This stores the new dataset version in the configured DVC remote.

## 9. Comparing Dataset Versions

Git can be used to view the history of the DVC metadata file:

```bash
git log --oneline -- data/raw/iris_v1.csv.dvc
```

This shows the commits associated with different versions of the dataset.

DVC can compare the dataset associated with a previous Git commit against the current dataset using:

```bash
dvc diff 602aa4a
```

The comparison identifies that:

```text
data/raw/iris_v1.csv
```

was modified between the two dataset versions.

The DVC metadata can also be inspected directly:

```bash
git show 602aa4a:data/raw/iris_v1.csv.dvc
```

and:

```bash
git show HEAD:data/raw/iris_v1.csv.dvc
```

The two files contain different dataset hashes, confirming that the underlying dataset content changed.

## 10. Restoring a Historical Dataset Version

DVC allows a previous dataset version to be reproduced using the DVC metadata stored in an earlier Git commit.

To restore the original 150-row dataset:

```bash
git checkout 602aa4a -- data/raw/iris_v1.csv.dvc

dvc checkout data/raw/iris_v1.csv.dvc
```

The restored dataset can be verified using:

```bash
wc -l data/raw/iris_v1.csv
```

Expected result:

```text
151
```

The 151 lines represent:

```text
150 data rows + 1 header
```

Thus, the exact historical dataset associated with the earlier Git commit can be reproduced.

---

## 11. Returning to the Latest Dataset Version

After reproducing the historical version, the latest DVC metadata can be restored:

```bash
git checkout HEAD -- data/raw/iris_v1.csv.dvc

dvc checkout data/raw/iris_v1.csv.dvc
```

The current dataset can then be verified:

```bash
wc -l data/raw/iris_v1.csv
```

Expected result:

```text
171
```

This represents:

```text
170 data rows + 1 header
```

Therefore, DVC allows the project to switch between historical and current dataset versions without manually copying or maintaining multiple CSV files.

## 12. Git and DVC Responsibilities

Git and DVC have different responsibilities in the workflow.

| Tool            | Responsibility                                                     |
| --------------- | ------------------------------------------------------------------ |
| **Git**         | Tracks source code, configuration, documentation, and DVC metadata |
| **DVC**         | Tracks dataset versions and manages dataset storage                |
| **DVC Remote**  | Stores the actual versioned dataset objects                        |
| **`.dvc` file** | Stores metadata and the hash identifying the dataset version       |

The workflow can be represented as:

```text
                 Git Repository
                       │
          ┌────────────┴────────────┐
          │                         │
     Source Code              DVC Metadata
     train.py                 iris_v1.csv.dvc
     augment_data.py                 │
          │                          │
          │                          ▼
          │                    Dataset Hash
          │                          │
          │                          ▼
          │                   DVC Remote
          │              ~/dvc-remote-storage
          │                          │
          │                          ▼
          └─────────────── Actual Dataset
```

## 14. Lessons Learned / Notes

* Git is not used to store the actual large dataset.
* DVC stores and versions the dataset while Git stores the corresponding DVC metadata.
* Every dataset change requires the `dvc add → git add → git commit → dvc push` cycle.
* A change in dataset content produces a different DVC hash.
* Git commits make it possible to identify which version of the dataset was associated with a particular experiment.
* `dvc diff` can be used to identify changes between dataset versions.
* `dvc checkout` can restore the exact dataset corresponding to a selected DVC metadata version.
* Combining Git and DVC provides reproducibility by allowing both code and data versions to be recovered together.

## 15. Summary Workflow

The complete workflow followed in this experiment is:

```bash
# Initialize DVC
dvc init

# Configure remote
mkdir -p ~/dvc-remote-storage
dvc remote add -d myremote ~/dvc-remote-storage

# Track dataset
dvc add data/raw/iris_v1.csv

# Track DVC metadata with Git
git add data/raw/iris_v1.csv.dvc data/raw/.gitignore
git commit -m "data: add iris_v1 raw dataset (150 rows) tracked via DVC"

# Upload dataset
dvc push

# Modify dataset
python src/augment_data.py

# Create new DVC version
dvc add data/raw/iris_v1.csv

# Commit metadata
git add data/raw/iris_v1.csv.dvc
git commit -m "data: augment iris dataset with 20 synthetic rows (150 -> 170)"

# Upload new dataset version
dvc push

# Compare versions
git log --oneline -- data/raw/iris_v1.csv.dvc
dvc diff 602aa4a

# Restore historical version
git checkout 602aa4a -- data/raw/iris_v1.csv.dvc
dvc checkout data/raw/iris_v1.csv.dvc

# Restore latest version
git checkout HEAD -- data/raw/iris_v1.csv.dvc
dvc checkout data/raw/iris_v1.csv.dvc
```
